# Phase 3 Manual Desktop UI Test Matrix

This checklist covers WPF behavior that backend contracts and view-model tests cannot fully prove on a staffed Windows terminal. It supplements automated correctness tests; it does not replace them. Run each scenario against a disposable shop using a test cashier and controlled inventory. Record the app version, Windows/printer details where relevant, scenario result, and sanitized evidence.

| ID | Area | Steps | Expected result | Result / evidence |
|---|---|---|---|---|
| UI-01 | Login and navigation | Sign in as cashier; move through POS, purchases, inventory, returns, warranty, supplier khata, Thaka, and settings; use back/navigation controls. | Only authorized pages/actions appear; navigation preserves usable layout and does not lose an in-progress form without warning. | Pending manual execution |
| UI-02 | POS scan and exact unit | Scan a known barcode and a serialized-unit code; select a product with multiple sale units. | Search resolves the expected product/unit; exact-unit and serialized identity remain visible through cart review. | Pending manual execution |
| UI-03 | Sale and receipt | Complete a cash and a bank sale; inspect the receipt and then open Sale History. | One sale is recorded; receipt totals, payment, cashier, and item units match the committed sale; sale is visible in history. | Pending manual execution |
| UI-04 | Draft and resume | Save a partial cart as a draft, navigate away, return to POS, and resume it. | Draft lines and selected units are restored once; the app does not create duplicate drafts after a retry. | Pending manual execution |
| UI-05 | Physical receiving | Receive a quantity item and a serialized item; close and reopen the receiving view after an ambiguous network response. | Committed units appear in inventory; retry resolves the same operation and does not receive twice. | Pending manual execution |
| UI-06 | Sale and purchase returns | Record an eligible sale return and purchase return; reopen a sale return after a simulated response loss. | Return disposition/refund and stock effects match the entered items; the same unresolved sale-return intent is resumed. | Pending manual execution |
| UI-07 | Stock adjustment and stocktake | Preview an adjustment, commit an authorized adjustment, then count and review a stocktake. | Preview is clearly separate from commit; blocked/conflicting actions show a clear message; counted units and final reconciliation are visible. | Pending manual execution |
| UI-08 | Warranty and replacement | Register a customer warranty claim, update custody/status, and complete an authorized replacement. | Claim identity, status, custody, and replacement are traceable; unavailable actions are disabled or explain the permission required. | Pending manual execution |
| UI-09 | Supplier khata and Thaka | Open a supplier ledger; record a payment; open a Thaka project and record a payment/settlement. | Balances and ledger rows refresh from backend results; repeating an unresolved action does not create a second entry. | Pending manual execution |
| UI-10 | Printing | Select an installed printer and supported media; preview, print, simulate printer failure, then choose retry/reprint deliberately. | Preview and media match selection; failure is understandable; the UI warns that physical output may be unknown and does not silently duplicate a job. | Pending manual execution |
| UI-11 | Backup and restore | Create a backup; select a verified backup; prepare, inspect, then explicitly cut over or discard using the displayed confirmation. | Only verified backups can be selected; prepare does not switch the active database; cutover requires deliberate confirmation; status is visible after navigating away and returning. | Pending manual execution |
| UI-12 | Permissions and expired session | Repeat representative write actions as cashier/manager; expire a session and attempt a write. | Denied/expired actions do not mutate data; the UI presents a concise reason and returns to sign-in when required. | Pending manual execution |
| UI-13 | Server unavailable / reconnect | Stop the test Server during a read and during a mutation; restore it and retry the unresolved operation. | Reads show a recoverable service message; mutation outcome is identified as unknown when appropriate; retry uses the same operation identity. | Pending manual execution |
| UI-14 | Busy, duplicate input, accessibility | Double-click a commit; use keyboard navigation in POS/settings; resize the window to supported minimum. | Duplicate submission is prevented; busy state is visible; focus order and labels remain usable; primary actions do not disappear or overlap. | Pending manual execution |

Do not use production credentials, live payment references, or production backup data during this exercise. A failed scenario should be captured with a sanitized screenshot and the matching operation/correlation ID before filing a defect.
